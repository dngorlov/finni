# Финни

Офлайн-игра для Android. Дети 7–11 лет учатся обращаться с деньгами, пока заботятся о пиксельном питомце. Ребёнок планирует день, выбирает между обязательным и желаемым, копит на цель и проходит уроки на карте Москвы. Каждое решение видно по балансу, копилке, сытости и счастью питомца.

Команда hsespbteam: Сергей Гончаров и Дмитрий Горлов (разработка), Андрей Мужевлёв (графика), Савва Власов (образовательный сценарий), Александр Лузин (требования).

Этот файл — сопроводительная документация прототипа 0.1.0. Тот же текст лежит отдельным документом: [docs/soprovoditelnaya-dokumentaciya.docx](./docs/soprovoditelnaya-dokumentaciya.docx). Числа экономики берутся из `src/core` и `assets/content`. Словарь терминов — [CONTEXT.md](./CONTEXT.md).

## 1. Назначение, состав репозитория и быстрый запуск

### Назначение

Финни учит трём решениям до покупки: потратить на обязательное, потратить на желаемое или отложить. Игровая валюта — монеты. Реальных платежей, рекламы, сети, аккаунта и сбора персональных данных нет. Ошибка в уроке объясняется и даёт попробовать ещё раз. Отдельная ошибка открывает задание «Почини рюкзак». Питомец не умирает, шкалы держатся в диапазоне 0–100.

| Механика        | Где в приложении         | Чему учит                                                                                      |
| --------------- | ------------------------ | ---------------------------------------------------------------------------------------------- |
| План дня        | Деньги → План            | Разделить монеты на обязательное, желаемое и копилку до покупок и потом сравнить план с фактом |
| Счета и магазин | Дом → Магазин, Итоги дня | Сначала оплатить счета дня (минимум на еду и витамины), потом желания                          |
| Цель и копилка  | Деньги → Копилка         | Выбрать цель, откладывать регулярно, видеть, через сколько дней она купится                    |
| Вклад           | Деньги → Банк            | Отдать монеты на срок и получить их обратно с процентами                                       |
| Уроки           | Карта                    | Три темы: бюджет, сбережения, платежи                                                          |

### Быстрый запуск

Нужны Node.js LTS 20 или новее и npm из того же комплекта. Для проверки логики устройство не требуется.

```bash
npm install
npx expo start          # Metro. Клавиша a — эмулятор или устройство, QR — Expo Go
npm test                # автоматические тесты
npm run typecheck       # tsc --noEmit
npm run lint            # eslint
```

Демо-режим для проверяющего: Настройки → «Взрослый раздел» → пример на умножение → «Демо-режим». Появляется отдельный профиль. План, Копилка и Банк открыты сразу, и на карте сразу открыты все уроки и мини-игры. «Сбросить демо» возвращает этот профиль к началу и не трогает профиль ребёнка.

## 2. Окружение и сборка релизного APK

Готового APK в репозитории нет: `*.apk` и каталог `android/` перечислены в `.gitignore`. Файл появляется после сборки и прикладывается к поставке отдельно.

### Инструменты

| Инструмент   | Версия в этой сборке                               |
| ------------ | -------------------------------------------------- |
| Node.js      | LTS 20 или новее                                   |
| npm          | тот, что идёт с Node                               |
| JDK          | 17                                                 |
| Android SDK  | platform API 26 или новее, build-tools ставит Expo |
| Expo SDK     | 57.0.24 (`expo` в `package.json`)                  |
| React Native | 0.86.3                                             |
| TypeScript   | 6.0.3                                              |

Переменная `ANDROID_HOME` должна указывать на SDK. Удобный способ поставить JDK и SDK - Android Studio.

### Сборка

```bash
npm install
npx expo run:android --variant release
```

Первый запуск создаёт `android/` (prebuild). APK:

`android/app/build/outputs/apk/release/app-release.apk`

Установка:

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Сейчас release подписывается debug-ключом, его создаёт локальная сборка Android. Для RuStore нужен свой keystore. Файлы `*.jks` и `*.key` в репозиторий не кладутся.

Проверка пакета после установки: имя «Финни», пакет `org.hseteamspb.finni`, версия 0.1.0. В Настройках та же версия и номер сборки 1.

### Демонстрационный сценарий

Сценарий идёт на установленном приложении, без сети. Обычный профиль открывает План, Копилку и Банк уроками, а точки карты — по цепочке. Демо-профиль открывает Деньги и всю карту сразу.

1. Первый запуск. Три карточки: зачем игра, цель, три решения. Затем вид и окрас питомца и имя. «Дальше» на имени записывает профиль и выдаёт 100 монет. Тур подсвечивает этот баланс.
2. Дом. Видны питомец, номер игрового дня, сытость, счастье, баланс и этап «Новичок».
3. Карта. Сначала открыт только «Что такое бюджет?». Пройти его до конца. Первое прохождение урока на карте закрывает игровой день и платит до 30 монет за верные ответы с первого раза. Урок открывает «Планирование бюджета», «Что такое сбережения», «Платежи» и свою мини-игру «Нужно или хочется?» в «Мини-играх».
4. Итоги дня. Разбор дня, план и факт, изменения шкал. Уход с экрана открывает следующий игровой день. Календарь для этого ждать не нужно.
5. Магазин. Купить «Обед» (12) и «Конфету» (5). На карточке товара до оплаты видны цена и прибавка к шкале. Покупка дороже баланса показывает, сколько не хватает, и предлагает «Выполнить задание». Списания нет.
6. После урока «Что такое сбережения» открывается Копилка. Выбрать цель этапа (например «Конструктор», 60), нажать «Положить», подтвердить сумму. Прогноз дней появляется после первого взноса.
7. После урока «Планирование бюджета» открывается План. Три кучки — обязательные, желаемые, копилка — в сумме не больше баланса. Подтвердить. В магазине и копилке видно, сколько от плана осталось.
8. После урока «Где живут накопления?» открывается Банк. Вклад от 10 монет: 3 дня и 10 % или 5 дней и 20 %. Досрочное снятие отсутствует. В день окончания срока монеты с процентами возвращаются на баланс.
9. Закрыть приложение и открыть снова. Профиль, монеты, цель и пройденные уроки на месте.
10. Настройки → «Взрослый раздел» → верный ответ на умножение двузначного на однозначное. Включить демо, сыграть ещё несколько дней подряд (каждый урок на карте закрывает день), затем «Сбросить демо». Выйти из демо: детский профиль прежний.
11. В том же разделе «Удалить профиль»: подтверждение и слово `удалить`. Снова открывается первый запуск.

## 3. Архитектура

Серверной части нет. Сетевых запросов в игре нет, поэтому схема развёртывания и спецификация OpenAPI не входят в поставку. Всё состояние лежит в SQLite на устройстве.

```
экран (src/ui)
    → репозиторий (src/data/repositories/gameRepository.ts)
        → правила (src/core)
        → SQLite (src/data/schema.ts, src/data/migrations.ts)
контент (assets/content/*.json) → проверка zod (src/data/content.ts)
```

| Слой             | Роль                                                                 | Примеры                                                                                     |
| ---------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `src/core`       | Формулы. Модуль не импортирует React и Expo, это проверяет eslint    | `economy.ts`, `savings.ts`, `bank.ts`, `stages.ts`, `tasks.ts`, `dailyReward.ts`            |
| `src/data`       | Запись сразу после действия. Миграции в транзакции                   | `gameRepository.ts`, `schema.ts`                                                            |
| `src/ui`         | Три вкладки: Дом, Карта, Деньги. Нижняя панель только на этих корнях | `MainScreen.tsx`, `ShopScreen.tsx`, `PlanScreen.tsx`, `SavingsScreen.tsx`, `BankScreen.tsx` |
| `assets/content` | Новый урок — правка JSON, без изменения движка                       | см. [docs/CONTENT.md](./docs/CONTENT.md)                                                    |

Навигация:

```
Запуск
 ├─ нет профиля → Первый запуск (3 карточки → питомец → имя) → Дом
 └─ есть профиль → Дом

Дом · Карта · Деньги
 ├─ Дом → питомец, подарок, цель, итоги, магазин
 ├─ Карта → урок → результат урока → карта
 │         первое прохождение урока на карте → итоги дня → следующий день
 ├─ Деньги → копилка · план · журнал · банк
 └─ Настройки → звук, анимация, внешний вид, достижения, «Как всё считается», авторы
                → взрослый раздел (гейт) → прогресс, демо, удаление
```

Решения записаны в [docs/adr](./docs/adr). Стек — [ADR-0001](./docs/adr/0001-react-native-expo-drizzle-expo-sqlite.md): React Native, Expo, TypeScript, Drizzle, expo-sqlite. Игровой день закрывает первое прохождение урока на карте — [ADR-0007](./docs/adr/0007-lesson-completion-ends-the-game-day.md). Этап растёт от покупки цели — [ADR-0008](./docs/adr/0008-stage-advances-by-buying-the-goal.md). Своей цели больше нет — [ADR-0015](./docs/adr/0015-no-custom-goal.md).

Закрытые инструменты:

| Инструмент | Когда открывается                              | В демо-режиме |
| ---------- | ---------------------------------------------- | ------------- |
| Магазин    | с первого дня                                  | с первого дня |
| Копилка    | урок «Что такое сбережения» (`savings_what`)   | сразу         |
| План       | урок «Планирование бюджета» (`budget_plan`)    | сразу         |
| Банк       | урок «Где живут накопления?» (`savings_where`) | сразу         |

## 4. Структура данных

База — одна SQLite на устройство. Схема Drizzle: `src/data/schema.ts`. DDL, который реально применяется: `src/data/migrations.ts`.

### Профиль

`profiles`: id, name, species, color, accessory, petName, balance, isDemo, contentVersion, createdAt, dailyRewardClaimed, dailyRewardClaimedOn.

Профиль ребёнка — это питомец: вид (`sp1`–`sp3`), окрас (`c1`–`c3`), аксессуар и имя питомца. Отдельного имени ребёнка первый запуск не спрашивает; поле `name` совпадает с `petName`. `isDemo = 1` помечает тестовый профиль. Два профиля живут рядом: детский и демо.

`meta`: пары ключ–значение. Активный профиль, флаги тура, громкость, анимация (`src/data/metaKeys.ts`).

### Игровая экономика

| Таблица            | Смысл                                                                                                 |
| ------------------ | ----------------------------------------------------------------------------------------------------- |
| `days`             | Игровой день `n` профиля. `closedAt` пустой, пока день открыт                                         |
| `plans`            | Обещание дня: mandatory, optional, savings, статус `draft` или `confirmed`                            |
| `transactions`     | Каждое движение монет: вид, знак суммы, подпись. Баланс профиля равен сумме его транзакций            |
| `purchases`        | Покупка: товар, цена, обязательная или желаемая, оплата с баланса или из копилки, куплена ли как цель |
| `savingsTransfers` | Взнос `in` и снятие `out`. Копилка = сумма `in` минус сумма `out`, не ниже нуля                       |
| `goals`            | Одна активная цель: ключ каталога. Поля name, icon, custom, threshold читаются только у своей цели, сохранённой до ADR-0015 |
| `deposits`         | Вклад: сумма, процент, срок в игровых днях, день открытия, день возврата, `open` или `paid`           |

Каталог товаров и цели — не строки базы, а `assets/content/catalog.json`. В базу попадает уже совершённая покупка и выбранная цель.

### Задания и прогресс

| Таблица        | Смысл                                                                                                                                     |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `taskProgress` | Урок: статус, выплаченные монеты, лучший результат, число верных первых ответов, число оценённых первых ответов, дата первого прохождения |
| `petState`     | Сытость `care`, счастье `mood` (0–100), этап 0/1/2, `stageCredit` — накопленная сумма дешёвых своих целей (только для целей, сохранённых до ADR-0015)                                   |
| `meterEvents`  | Каждое изменение шкалы: какая шкала, дельта, причина                                                                                      |
| `dayScores`    | Снимок закрытого дня: счета оплачены, уложился в план, был взнос, старое число очков. На этап это число не влияет                         |
| `achievements` | Полученное достижение, день и флаг «уже показали»                                                                                         |

Урок в контенте (`assets/content/tasks.json`): id, тема `budget` | `savings` | `payments`, порядок, сложность, награда, описание, точка на карте, цепочка `nodes`. Узел — карточка, вопрос, сортировка или игра (`allocate`, `compare`, `replan`, `steps`, `dream`). Мини-игра ссылается на урок полем `parent` и не имеет точки на карте.

## 6. Баланс, награды, состояние и рост питомца

Константы: `src/core/config.ts`. Шкалы обрезаются до 0–100 функцией `applyMeterDelta`. Эти же правила ребёнок и взрослый видят в приложении: Настройки → «Как всё считается» (`src/ui/screens/RulesScreen.tsx`). Числа на этом экране собираются из `config.ts`, `catalog.json`, `tasks.json` и функций `src/core`, а не пишутся вручную (`src/ui/rules.ts`).

### Откуда берутся монеты

| Источник           | Правило                                                                                                            | Когда видно ребёнку                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| Стартовый бюджет   | 100 один раз, в момент «Дальше» на имени                                                                           | Тур «Твой первый бюджет» на Доме      |
| Урок               | `награда × очки первых ответов / число оцениваемых шагов`, округление, не выше награды урока                       | Карточка результата: источник и сумма |
| Повтор урока       | доплата только разницы с лучшим прошлым результатом                                                                | «Можно получить ещё N» на точке карты |
| Ежедневный подарок | дорожка 5, 5, 10, 10, 15, 15, 20 и снова сначала. Один шаг за календарный день. Пропущенный день место не сдвигает | Дом, кнопка «Подарок»                 |
| Вклад              | сумма + целые проценты вниз: `floor(сумма × процент / 100)`                                                        | В день срока: «Вклад вернулся»        |

Очки ответа: верный = 1, «с ценой» = 0,5, неверный = 0. В оценку входят вопросы и каждая фишка сортировки. Карточки теории и игры «распредели», «сравни», «пересобери», «шаг за шагом», «финансовая мечта» в долю не входят: если оцениваемых шагов нет, выплачивается вся награда.

Урок на карте платит до 30 или 35 монет, и его первое прохождение закрывает игровой день. Мини-игра платит до 10 или 15 и день не закрывает. «Почини рюкзак» платит 10 один раз.

Пример награды. Урок на 30 монет, четыре вопроса, с первого раза два верных, один «с ценой» и один неверный: очки 2 + 0,5 + 0 = 2,5. Монеты = round(30 × 2,5 / 4) = 19.

### План, покупка, копилка, банк

План — обещание. Монеты остаются на балансе, пока ребёнок не купит товар или не положит их в копилку или вклад.

- План верен, если обязательные + желаемые + копилка ≤ баланс и обязательные ≥ счета этого дня (но не выше баланса).
- Счета — это минимум на обязательное (еда и витамины), любой набор обязательных покупок. Минимум повторяется по кругу из 5 дней (`catalog.json`, поле `bills`): 20, 22, 25, 22, 20. Правило команды: 20–25 монет в день хватает, чтобы закрыть ежедневные −15 сытости (например, суп + витамины = 13 монет дают сытость +17 и счастье +2).
- Старые сохранения: у покупки в базе свои цена и вид, поэтому строки журнала с прежними товарами (обед, проезд, лекарство и др.) читаются по имени и попадают в свою корзину. Миграции базы не нужны.
- Покупка проходит, если баланс ≥ цены. Иначе не хватает `цена − баланс`, списание не делается.
- Прогноз цели: `ceil(остаток / среднее последних взносов)`, окно 5 взносов. До первого взноса на экране «—».
- Вклад: минимум 10. Предложения: 3 игровых дня и 10 %, 5 дней и 20 %. Возврат в день `день открытия + срок`. Пример: 100 монет на 3 дня под 10 % возвращают 110.

### Как решение становится состоянием питомца

Старт профиля: сытость 50, счастье 50, этап Новичок.

Каждая покупка сразу прибавляет свою шкалу. В конце игрового дня сытость и счастье падают на 15 каждая. Прибавка покупки это падение не отменяет, она уже лежит на шкале сверху.

| Событие                                    | Сытость | Счастье                        |
| ------------------------------------------ | ------- | ------------------------------ |
| Конец любого игрового дня                  | −15     | −15                            |
| Суп, 8 монет (обязательное)                | +12     | —                              |
| Вишня, 3 (обязательное)                    | +2      | +2                             |
| Чай, 2 (обязательное)                      | +2      | +1                             |
| Витамины, 5 (обязательное)                 | +5      | +2, курс: до +5 (см. ниже)     |
| Плюшевый мишка, 15 (желаемое)              | —       | +22                            |
| Мороженое, 4 (желаемое)                    | +1      | +5, надоедает: до +1 (см. ниже) |
| Билет в кино, 10 (желаемое)                | —       | +15                            |
| Пицца, 15 (желаемое)                       | +10     | +5                             |
| Желаемые потрачены больше, чем обещал план | —       | ещё −5 в конце дня             |
| План был открыт и его не подтвердили       | —       | ещё −10 в конце дня            |
| Покупка цели из копилки                    | —       | прибавка цели: от +92 до +100 (поле `effect` в `catalog.json`); сохранённая до ADR-0015 своя цель: +10 |

Привычки (`src/core/habits.ts`, поле `habit` товара в `catalog.json`, проверяется схемой). «Подряд» — число прошлых игровых дней подряд (N−1, N−2, …), в которые товар покупали хотя бы раз. Сегодняшние покупки не считаются, поэтому все покупки товара за один день дают одинаковое счастье; пропущенный день обнуляет счёт. Счёт берётся из уже сохранённых покупок (товар и игровой день), новых полей в базе нет. Сытость не меняется.

| Товар     | `habit`                                  | Счастье за покупку                           | Подряд 0 / 1 / 2 / 3 / 4+ |
| --------- | ---------------------------------------- | -------------------------------------------- | ------------------------- |
| Витамины  | `{"kind":"grow","step":1,"max":3}`       | `2 + min(3, подряд)` — курс                   | +2 / +3 / +4 / +5 / +5    |
| Мороженое | `{"kind":"fade","step":1,"min":1}`       | `max(1, 5 − подряд)` — надоедает              | +5 / +4 / +3 / +2 / +1    |

На карточке Магазина у такого товара шкала из делений (витамины — 3, мороженое — 4), заполненная по «подряд», и рядом сегодняшнее счастье: «Курс: +N» или «Надоедает: +N». Карточка, окно покупки и чек показывают то же число, что попадает на шкалу. Тесты: `habits.test.ts`, `habitFlow.test.tsx`, `gameRepository.node.test.ts`.

День, который закрывает сам урок «Планирование бюджета», штраф за неподтверждённый план не берёт: план открылся только что. Закрытый урок план не штрафует. В демо-режиме план открыт с начала, и штраф действует.

Пример одного дня (день 1, счета — минимум 20). Старт 50/50, баланс 100. Куплены суп, витамины, вишня и два чая (8 + 5 + 3 + 2 + 2 = 20, счета оплачены) и мороженое за 4; план желаемых был не меньше 4, план подтверждён. Сразу после покупок: баланс 76, сытость 50 + 12 + 5 + 2 + 2 + 2 + 1 = 74, счастье 50 + 2 + 2 + 1 + 1 + 5 = 61. Конец дня: сытость 59, счастье 46. Если мороженое было сверх плана, счастье стало бы 41. Если купить только мороженое, сытость к концу дня 36: питомец голоднее, игра при этом продолжается. Шкалы всегда остаются в пределах 0–100.

Поза на Доме (`src/ui/pet/keys.ts`): обе шкалы ≥ 70 — радость; любая шкала < 30 — грусть; иначе обычная поза.

### Рост этапа

Этапы: Новичок → Про → Миллионер. Единственный шаг — покупка цели.

Порог этапа — цена самой дешёвой готовой цели этого этапа: Новичок 60 (конструктор), Про 120 (набор для рисования), Миллионер 220 (гитара).

- Цель выбирается только из трёх готовых целей текущего этапа ([ADR-0015](./docs/adr/0015-no-custom-goal.md)). Покупка любой из них поднимает этап на один и обнуляет накопленную сумму.
- Своя цель, сохранённая до ADR-0015, по-прежнему читается: по цене не ниже порога она поднимает этап, дешевле порога — прибавляет свою цену к сумме, и этап растёт, когда сумма достигает порога. Новую свою цель создать нельзя.
- На Миллионере следующего этапа нет.
- Аксессуар надевается вместе с этапом: на Новичке нет, на Про — очки, на Миллионере — шапочка с антенной. Внешний вид в Настройках меняет вид, окрас и уже открытый аксессуар.

Ребёнку на копилке говорится «Теперь ты Про!» или «Теперь ты Миллионер!». Порог показывается только у сохранённой своей цели, пока она дешевле порога и следующий этап есть.

Разбор дня (`src/core/dayInsights.ts`) собирает до трёх фраз: сначала что получилось, затем один совет. Тексты конкретные и без оценки ребёнка. Итоги хранят этот разбор, план против факта и изменения шкал.

## 8. UX/UI и доступность

Обоснование решений:

- Три вкладки разделяют питомца, учёбу и деньги. Ребёнок не ищет нужный раздел в длинном меню.
- План устроен как обещание: монеты остаются на балансе до покупки или взноса, и это написано на экране. Так видно разницу между «я решил» и «я заплатил».
- Каждое движение монет заканчивается карточкой: сумма, шкала и причина. Баланс не меняется молча.
- Разбор дня хвалит конкретное действие и даёт один совет. Оценки ребёнка и стыда в текстах нет.
- Взрослый раздел закрыт примером на умножение (двузначное на однозначное, новый пример после ошибки). Ребёнку 7–11 туда попасть трудно, пароль при этом не хранится.
- Пиксельный шрифт — лицо игры. Длинный заголовок «Карта заданий» остаётся системным шрифтом, потому что пиксельный на этой строке не помещается.
- Палитра — светлая схема Material 3. Пары «текст на фоне» подобраны под WCAG AA: текст на фоне около 13:1, акцент на фоне около 6:1, подпись на оранжевой кнопке около 4,6:1 (`src/ui/theme.ts`).
- Ошибка безопасна: шкалы не падают ниже нуля, питомец остаётся, исправление — отдельное задание.
- Все формулы открыты: Настройки → «Как всё считается». Шесть коротких разделов (монеты, план дня, покупки и шкалы, копилка и цели, банк, этапы) с числами из кода игры. Экран прокручивается и читается при крупном системном шрифте.

## 9. Разрешения, данные и удаление профиля

Разрешения Android не запрашиваются: в `app.json` массив `android.permissions` пуст. Дополнительно заблокированы запись звука, микрофон, службы переднего плана и уведомления — их мог бы подтянуть модуль звука.

Что хранится на устройстве, в SQLite, и никуда не отправляется:

- имя питомца и его внешность;
- монеты, покупки, план, копилка, вклады, цели, уроки, дни, шкалы, достижения;
- громкость и переключатель анимации;
- место на дорожке ежедневного подарка и календарная дата последнего получения.

Аналитики, рекламных SDK и учётной записи нет. Имя ребёнка, школа, контакты и геолокация не спрашиваются.

Удаление, всё из Настройки → «Взрослый раздел» (на демо-профиле кнопки сброса детского профиля скрыты):

| Действие           | Что происходит                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| Сбросить прогресс  | Подтверждение, затем слово `сбросить`. Имя и внешность остаются, экономика и уроки начинаются заново          |
| Удалить профиль    | Подтверждение, затем слово `удалить`. С устройства уходят детский профиль и демо-профиль. Снова первый запуск |
| Сбросить демо      | Отдельное подтверждение. Демо возвращается к первому дню, детский профиль не меняется                         |
| Удалить приложение | Система Android стирает базу, включая имена и настройки звука                                                 |

Реализация удаления строк: `deleteProfile` в `src/data/repositories/gameRepository.ts` и `src/ui/session/childProgress.ts`.

## 11. Ограничения прототипа и дальнейшее развитие

Ограничения текущей сборки:

- Этап растёт от покупки цели. Очки дня по-прежнему записываются и на этап не влияют.
- Родительский бонус не сделан.
- Помощник с ответами на вопросы про деньги не сделан. Игра его не требует.
- Альбомная ориентация и отдельная вёрстка планшета не делались. Портрет и ширина от 360 dp — рабочий режим.
- Release подписывается debug-ключом. APK в git не хранится.
- Проверка на физическом устройстве в репозиторий не записана.
- `docs/ROADMAP.md` и часть `docs/REQUIREMENTS.md` описывают более ранние решения (ежедневное пособие, этапы Друг и Мастер, календарный день). Для этой сборки верны разделы 3–7 этого файла.

Дальше, по порядку, без ломки уже играемого цикла:

1. Дописать в раздел 10 результат прогона TC-1–TC-12 на физическом устройстве с Android 8 или новее.
2. Подписать release своим keystore и приложить APK к поставке.
3. Родительский бонус: +5 / +10 / +20 не чаще одного раза за игровой день, с необязательной причиной, записью в журнал.
4. Планшет и альбомная ориентация.
5. Помощник на Доме остаётся выключенным по умолчанию: без персональных данных в запросе, без ссылок в ответе, с явным сообщением, если сети нет.
